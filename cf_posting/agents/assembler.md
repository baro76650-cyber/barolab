# CF 조립: 행동 설명과 실제 자료를 한 흐름으로 연결한다

같은 실행의 키워드·리서치·원고·독자 과제·이미지 계획·실제 자산을 인수해 `final.html`, `final.md`, `assembled.html`을 조립한다. 글의 의미·조건·실행 결과를 보존하고 이미지나 서식만 갖춘 상태를 해결 완료로 처리하지 않는다.

## 본문과 이미지 연결

현재 실행의 `article.json.contentHtml`과 `readerTask`를 기준으로 한다. `blockRef`와 `anchorId`는 실제 본문의 HTML `id`를 가리켜야 한다. 사용법의 행동·결과·문제 대처가 메타데이터에만 있고 본문에 없는지 확인한다.

관련 figure는 해당 `anchorId` 블록 바로 뒤에 배치한다. 기존 `sectionIndex`는 절 단위 배치가 필요한 기존 자료에만 호환용으로 사용한다. 중요한 단계의 캡처를 글 맨 앞이나 끝에 몰지 않는다. 독자가 행동 설명을 읽고 바로 해당 화면에서 위치와 결과를 찾을 수 있어야 한다.

`imagePlans`와 실제 파일·source·role·단계의 관계를 대조한다. `capture`는 실제 실행 자료, `generated`는 설명용 생성물임을 내부 기록으로 확인한다. 파일 존재만으로 진짜 조작 화면이라고 판정하지 않는다. 실제 캡처가 필요한 빈자리에 분위기 사진이나 가짜 UI를 넣지 않는다.

## 읽기와 결과 확인

- 메뉴·값·포인터가 필요한 장면은 모바일에서도 핵심 부분이 읽히게 배치한다. 필요하면 원본을 보존한 부분 확대를 연결하고 전체 맥락을 잃지 않게 한다.
- 캡션은 figure의 figcaption에 한 번만 표시한다. 행동·위치·결과를 간결하게 설명하며 본문 문단에 중복하지 않는다.
- 표에는 헤더·셀 여백·구분선·필요한 모바일 가로 스크롤을 두고 행·열 의미를 보존한다.
- 제목과 H2/H3의 위계는 실제 질문·작업 순서와 맞춘다. 고정 소제목 수, 가운데 정렬, 감사 인사, 해시태그를 강제하지 않는다.
- 내부 프롬프트·작업 로그·미완료 플레이스홀더는 공개 완료본에 남기지 않는다. 필수 자산이 없으면 조립 완료로 승인하지 않는다.

## 인계와 검수

`assemblyReadyForLayoutReview`는 구조와 자료가 후속 실제 렌더 검수에 넘길 준비가 되었는지 판정한다. 후속 PC·모바일 완성 화면 검수 자료가 아직 없다는 이유만으로 조립 결함으로 삼지 않는다. 누락된 필수 자산, 미완료 플레이스홀더, 잘못된 anchor·이미지 위치·캡션 등 실제 조립 오류는 계속 반려한다. 실제 완성 화면의 독립 검수와 최종 승인 여부는 후속 reviewer가 판단한다.

PC와 모바일의 실제 완성 문서를 처음부터 끝까지 확인할 수 있는 산출물을 제공한다. HTML 생성만으로 실제 화면 검수가 끝났다고 보고하지 않는다. 깨진 이미지·읽기 어려운 캡처·어긋난 단계 연결을 구체적으로 남긴다.

이미지나 본문 변경 시 관련 해시·인계 기록을 갱신하고 독립 최종 검수를 다시 받는다. 자료가 올바른 부분은 보존하고 필요한 수정만 수행한다. 기존 공개 글의 ID·URL·발행일을 바꾸거나 조립 완료를 게시 완료로 보고하지 않는다.

# CF 키워드 선정: 독자가 끝낼 질문부터 정한다

CF의 주요 검색 독자는 구글·빙에서 답이나 해결 방법을 찾는 사람이다. 상시 궁금증, 새로 생긴 문제, 앞으로 생길 질문을 모두 후보로 삼는다. 이슈성이나 자극적인 제목만으로 선정하지 않는다.

## 선정과 수요 확인

- 메인 검색어와 독자의 구체적인 질문을 구분한다. `구글 스프레드시트`는 대상이고, `누가 바꾼 셀인지 확인하고 필요한 값만 되돌리기`는 해결할 과제다.
- 시작 상태·필요한 권한이나 준비물·완료 상태를 설명할 수 있어야 한다. 글을 읽은 독자가 무엇을 알거나 선택하거나 실행할 수 있는지 적는다.
- 검색량·자동완성·최근 질문·제품 변경 등 실제 조회한 수요 신호와 시각을 남긴다. 미조회 값을 0으로 바꾸거나 추정치를 실측으로 쓰지 않는다. 네이버 검색량은 참고 신호이며 구글·빙 검색량이나 순위를 뜻하지 않는다.
- 기존 수요 수집 계약이 요구하는 필드는 실제 관측으로 채운다. 질문 수를 채우기 위해 같은 질문을 반복하거나 최근 이슈가 없다는 이유만으로 지속적인 문제를 배제하지 않는다.

## 기존 글 확인

호스트가 실제로 끝까지 조회한 발행 목록의 ID·제목·주소·분류와 질문을 비교한다. 일부 조회나 실패를 전체 점검으로 기록하지 않는다. 동일 질문을 해결하는 글은 기존 글 수정으로 분류한다. 제목·연도·동의어·슬러그 접미사를 바꿔 신규 글로 만들지 않는다. 같은 제품의 다른 문제라면 해결 결과의 차이를 적는다.

기존 글 수정은 ID·slug·publicUrl·publishedAt을 보존한다. 검수 실패를 신규 발행 대기로 바꾸거나 수정 시각으로 원발행일과 오늘 신규 발행 수를 바꾸지 않는다.

## 인계

`keywords.md`에 주 키워드, 독자 질문, 수요 관측 범위, 시작 상태, 완료 조건, 분류, 중복 판단, 조사할 비교 문서와 직접 실행할 과제를 기록한다. 실제로 보지 않은 순위나 경쟁 문서의 부재를 단정하지 않는다. 다음 단계가 키워드 표현보다 해결 과제를 인수하게 한다.

CF는 키워드 → 리서치·실행 계획 → 원고·시각자료 → 조립 → 독립 검수 순서다. 이번 호출의 JSON 출력 계약을 따르고, 호스트가 같은 실행 폴더의 산출물과 모델·시각·입출력 지문을 `handoff.json`에 기록한다. 모델 호출이나 자료 수집 실패를 빈 산출물로 대체하지 않는다.

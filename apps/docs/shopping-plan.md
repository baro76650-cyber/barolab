# 말로 장보기 — 음성 장보기 메모

패키지 `com.barolab.voicebasket`, native Java, Android 8(API26) 이상·target36. V1 목표는 장보기 중 잊는 항목과 다시 입력하는 수고를 줄이는 것이다. 구현 완료와 실제 기기 검증·Play 내부 출시를 구분하고, 출시 증거 전에는 공개 서비스로 표시하지 않는다.

## 사용자와 차별점

손이 바쁘거나 큰 글씨를 선호하는 사용자가 장보기 전에 여러 목록을 만들고, 매장에서 체크하며, 다음 장보기 때 재사용한다. 카드 생성 앱과 달리 체크리스트에 집중한 teal·따뜻한 coral과 큰 조작을 쓴다. 핵심 차별점은 음성을 바로 확정하지 않고 수정·분리 미리보기 후 추가하는 점, 진행 중 광고가 없는 점, 전체 삭제 대신 보관하는 점이다. 인식 정확도·완전 오프라인·자동 수량 이해를 보장하지 않는다.

## V1 동선과 실제 범위

1. 목록 개요에서 이름을 정해 여러 장보기 목록을 만든다. 활성·보관·템플릿을 분리한다.
2. 상세에서 키보드로 쉼표·줄바꿈 입력 또는 마이크를 선택한다. 인식 결과는 입력창에만 들어오며 목록에 자동 추가하지 않는다.
3. 사용자가 원문을 고치고 ‘나눌 항목 미리보기’를 누른다. 기본 구분자는 쉼표·줄바꿈이며 독립 어절 ‘그리고·및·또는·하고’ 분리는 기본 꺼진 선택 기능이다. 붙인 말은 추론하지 않는다. 수량도 임의 해석하지 않는다.
4. 미리보기와 실제 추가 입력이 동일한지 다시 검사한 뒤 확인 버튼으로 추가한다. 이름이 정확히 같은 항목을 하나만 유지하는 옵션은 기본 꺼져 있다. 비슷한 이름·단위·의미를 합치지 않는다. 수량은 1로 시작하며 직접 ‘2개’, ‘1봉’ 등으로 편집한다.
5. 항목 체크·수정·삭제·목록 이름 변경. 직전 한 번의 데이터 변경은 앱을 재시작해도 되돌리기로 복원한다. 두 번 이상의 기록이나 복원 후 재실행을 보장하지 않는다.
6. 장보기 완료는 모든 항목을 보관함에 유지한다. 보관 복원 또는 새 목록으로 재사용한다. 템플릿은 원본을 보존하고 체크가 풀린 복사본으로 다시 사용한다.
7. 목록 텍스트를 Android 공유 선택기로 전달한다. 큰 글씨 18/22/28sp와 시스템 글씨 설정을 반영한다.

입력 상한: 목록 100개, 목록당 500항목, 한 번에 100항목, 항목 이름 120자, 목록명 60자, 수량 30자, 분리 입력 12,000자. 초과하면 이유를 보여 주며 데이터를 조용히 자르지 않는다. 현재 마지막 한 단계 복원은 데이터 변경용이며 미확정 입력을 자동 저장하는 클라우드 기능은 없다. 회전에는 입력 원문·미리보기·옵션을 Bundle로 보존한다.

## 음성과 권한·데이터 처리

- `RECORD_AUDIO`는 사용자가 마이크를 선택할 때만 요청한다. 거부해도 키보드 입력은 계속 가능하며 자동 권한 재요청 루프를 만들지 않는다.
- API31 이상에서 `isOnDeviceRecognitionAvailable` 확인 후 `createOnDeviceSpeechRecognizer`를 사용한다. 기기 서비스 존재가 한국어 모델 설치를 보장하지 않는다. 한국어 오류가 나면 설명하며 네트워크 인식으로 자동 전환하지 않는다.
- 온디바이스가 없으면 매회 음성 제공자의 서버 전송·네트워크 가능성을 설명하고 선택을 받은 뒤 일반 `SpeechRecognizer`를 사용한다. 앱의 설정 하나로 제공자 보관·삭제 정책을 통제한다고 주장하지 않는다.
- `EXTRA_PREFER_OFFLINE`만으로 오프라인을 보장하지 않는다. 서비스 호출·listener·중지·종료는 main thread, 세션 generation으로 이전 콜백 무시. ‘끝내기’는 결과를 기다리고 ‘취소’는 결과를 버린다. onPause/회전/종료 때 cancel+destroy, 45초 제한, 지속 녹음 없음. 앱이 녹음 파일을 보관하지 않는다.
- 목록·수량·체크·복원은 SharedPreferences JSON으로 로컬에만 저장한다. commit 성공 후만 메모리 상태를 교체한다. 서버·계정·앱 분석 SDK 없음. 기기 백업/이전 제외. 앱 데이터 삭제·앱 제거로 로컬 데이터가 사라진다.
- 다른 앱으로 공유한 사본에는 받는 앱 정책이 적용된다. 항목 텍스트·목록 이름·음성·종교/건강 같은 관심 분류를 광고 요청으로 전달하지 않는다.
- Google 광고·동의 SDK의 식별자·IP 기반 대략적 위치·광고/앱 상호작용·진단 처리는 별도 개인정보·Play 데이터 보안에 정확히 공개해야 한다. NPA도 수집 없음이 아니다.

공식 근거: [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer), [RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent). API는 원격 서버로 음성을 보낼 가능성, main thread, destroy 의무, RecognitionService queries 선언을 명시한다. 실기기별 제공자·언어 설치 상태는 별도 QA다.

## 광고·수익 가정과 측정

광고는 목록 개요 하단 공통 배너만 사용한다. 상세 체크·항목 입력·음성·미리보기·공유 중 배너를 숨긴다. 전면·보상형·음성 시작 전 광고는 없다. 내부 테스트는 Google 테스트 ID만 사용하며 실제 수익은 0이라고 추정하지 않고 ‘측정 전’으로 둔다.

수익 시나리오는 `개요 배너 노출 / 1,000 × 실제 eCPM`이다. 예를 들어 월 유효 노출 10,000회·가정 eCPM 1,000원이면 월 10,000원이라는 산술 예시일 뿐 매출 예측이 아니다. 광고 요청 수와 실제 노출, 앱 사용과 구매 결과를 혼동하지 않는다. 광고·호스팅·개발/유지보수 비용을 차감해 판단하며 상시 유료 생성 모델 호출은 사용하지 않는다.

V1에는 자체 행동 추적을 추가하지 않는다. Play의 집계 설치·유지율/안정성, AdMob의 노출·수익, 동의한 사용자 인터뷰/관찰로 측정한다. 항목·음성 원문을 지표 수집용 로그로 남기지 않는다. 신규 분석 SDK 도입은 처리 목적·동의·데이터 보안 변경을 선행한다.

실험 순서: (1) 키보드만으로 새 목록→3개 추가→수량 수정→체크→보관→재사용 완주 (2) 동의한 실제 한국어 화자의 음성 결과 수정량과 추가 실패 원인 관찰, 작은 표본 수 명시 (3) 마이크 권한 거부 후 입력 완주 (4) 큰 글씨/매장 환경에서 체크 성공과 오조작 관찰. 수익보다 핵심 완주와 데이터 손실 여부를 먼저 본다. 음성 인식률과 설치 수를 임의 KPI 성공으로 부풀리지 않는다.

## QA 수락 기준과 출시 게이트

- 파서: 쉼표/CRLF/빈 항목/접속어 옵션/붙인 ‘하고’/수량 문자열/정확 중복/상한 검증. 추측으로 제품명을 만들지 않는다.
- 데이터: 여러 목록 독립·수량·체크 저장, 재실행·회전, 항목 삭제 undo, 완료 보관 undo, 템플릿 원본 불변/복사 체크 해제, 저장 실패 원본 보존.
- 음성: 온디바이스 한국어 성공은 실제 음성 근거 필요. 에뮬레이터 서비스 없음·권한 거부·네트워크 선택·오류·빠른 취소·45초 timeout·홈/잠금/회전에서 마이크 해제와 늦은 콜백 무시를 구분 검증한다. 테스트 주입 텍스트를 음성 인식 성공으로 표시하지 않는다.
- UI: 세로/가로·시스템 font1.3·앱28sp·키보드 표시에서도 입력/추가/되돌리기 접근 가능. 목록 개요 이외 광고 영역이 나타나지 않아야 한다. 공유 시트만 열고 실제 다른 사람에게 전송하지 않는다.
- 출시 전 독립 리뷰, build/lint, 실제 앱 화면, package/서명/AAB 일치, 공개 개인정보·지원 URL, 데이터 보안·음성 전송 안내, 광고 테스트 ID/동의 상태를 확인한다. Play 내부 테스트와 정식 공개는 구분한다.

## 0.2.0 핵심 UX 구현과 검증 대기

매장 상세는 간결한 텍스트 행과 큰 체크 영역, 남은 수, ‘살 것/구입한 것’ 구역으로 바꿨다. 수정은 보조 버튼이며 체크·항목 변경 후 가까운 행의 스크롤 위치와 접근성 초점을 복원하도록 구현했다. 실제 기기에서의 오조작 감소나 접근성 성공은 아직 측정하지 않았다.

입력은 한 작업 영역에서 원문 수정→미리보기→명시적 추가로 이어진다. 접속어·정확 중복 옵션은 접힌 고급 옵션에 두고, 고정된 미리보기/추가 버튼은 서로 다른 동작을 유지한다. 원문이나 옵션이 바뀌면 이전 미리보기는 무효가 된다. 처리 토큰과 저장된 요청 ID로 연타·중복 커밋을 막고 저장 실패 때는 입력을 유지한다.

템플릿·보관 목록에서는 원하는 항목을 선택해 새 목록을 만든다. 원본을 바꾸지 않고 선택한 이름·수량을 복사하며 체크를 해제하고 새 항목 ID를 준다. 이름·선택·요청 토큰은 회전 때 보존하고 같은 생성 요청의 재처리는 기존 결과를 반환한다. 미확정 입력은 앱 프로세스 종료 후 영속 보존을 약속하지 않는다.

2026-10-14 통합 빌드·런타임 QA 범위는 qa/v2-build-verification.json에 기록했고, 19:10 KST v2 내부 테스터 제공은 qa/play-shopping-v2-internal-release.txt로 확인했다. 정식 공개는 미완료이며 한국어 실제 음성 성공은 실폰 검증 전이다. 회귀 기준은 중간 스크롤 체크/되돌리기, 미리보기 뒤 원문 수정과 추가 연타, 일부 항목 재사용의 원본·수량·체크 상태, 회전, 시스템 글씨 1.3/앱 28sp와 키보드·가로 화면의 확인 버튼 접근이다. 개별 시나리오 성공 여부는 QA 기록의 실제 관측 범위를 따른다.

이번 bounded 초안은 외부 임시 작업 `shopping-v2-draft/task.txt`로 실제 라우팅했다. 인증 FreeLLMAPI auto는 2,051ms 후 실패했고, 정책 fallback agy의 요청 모델 `gemini-3.8-flash-medium`은 17,163ms에 성공했다(반환 모델 미제공, 입력 12,973/출력 1,503토큰). 후보의 원본 항목 ID 복사·수량 정수화·저장 성공 무시 구현은 폐기했다. 기존 문자열 수량·새 ID·commit 성공 확인과 맞춰 수동 구현했으며 모델 코드를 자동 실행·적용하지 않았다. 파서 기존 6개와 요청 가드 3개 테스트를 빌드 담당에게 전달했다. 실행 결과는 별도 QA 근거로 기록한다.

## 실제 API 초안 검토 기록

인증 FreeLLMAPI `auto`로 bounded 구조 검토를 실제 실행했다. 초안의 잘못된 `createSpeechRecognizer` 서명, 권한을 onPause에서 철회하라는 설명, 광고를 설정에 표시한다는 제안은 폐기했다. 공식 API와 사용자 범위대로 온디바이스 factory·권한 유지/세션 해제·개요 배너 정책을 수동 통합했다. 후보 코드를 자동 실행·적용하지 않았다.

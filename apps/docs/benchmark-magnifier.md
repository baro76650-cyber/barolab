# 돋보기 경쟁 비교와 다음 개선 기준

확인일: 2026-10-14. 대상 제품은 `큰글씨 돋보기 - 확대·손전등` 내부 버전 0.1.0이다. 이번 작업은 조사와 제안이며 앱 소스·스토어·배포 상태를 바꾸지 않았다.

## 증거 범위

상용 2앱은 공식 Play 설명·표시된 리뷰·스토어 스크린샷을 조사했다. 설치하거나 실행하지 않았으며, 리뷰 3개씩의 공개 표본을 전체 사용자 의견으로 일반화하지 않는다. 스토어 그림은 마케팅 자료라 실제 현재 UI와 다를 수 있다. 상용 APK는 현재 환경에서 정당한 직접 취득 경로를 확보하지 않아 분석하지 않았다. 별도로 공식 저자가 공개한 오픈소스 APK 한 개를 REA로 정적 분석했다. 이는 인기 상용앱을 역분석했다는 의미가 아니다.

|---|---|---|
| [RV AppStudios Magnifying Glass + Flashlight](https://play.google.com/store/apps/details?id=com.rvappstudios.magnifyingglass&hl=en) | 설명은 조명·확대·고대비·사진 보관을 제시한다. Mark Sargent(2020-07-01)는 한 손으로 조절하는 세로 슬라이더를 장점으로 들었다. 모두 해당 시점의 개별 경험이다. | 첫 두 공식 그림은 약병의 작은 글자를 크게 보여주는 사용 장면과 확대 효용을 강조한다. 이 그림만으로 현재 버튼 위치·실제 배율·인식 품질을 확인할 수 없다. |
| [Sunfire Magnifying Glass + Flashlight](https://play.google.com/store/apps/details?id=com.sunfire.magnifyingglass&hl=en) | 설명은 확대·조명·촬영·정지를 제시한다. 각 출처에서 가져온 내용은 필요한 범위의 요약이다. 원본 그림 4개와 URL·다운로드 SHA는 `qa/competitor-rea/magnifier/play-sources.json`에 기록했다. 우리 에뮬레이터 화면 `qa/screenshots/magnifier-final-01-live.png`는 별도로 보았으며 실제 약병·동전 촬영 검증으로 취급하지 않는다.

## 실제 REA 기술 비교

비교 대상은 [cvzi/magnifyingglass 공식 v1.1 릴리스](https://github.com/cvzi/magnifyingglass/releases/tag/v1.1)의 `mag2.apk`다. [저장소](https://github.com/cvzi/magnifyingglass)는 저시력용 확대·고대비·정지·저장을 설명하고 Apache 2.0 라이선스를 명시한다. 코드·그림·상표를 우리 앱에 복사하지 않았다.

- 실제 APK: package `magnifying.glassopensource`, versionName `1.1`, versionCode `2`, minSdk 30, targetSdk 36.
- SHA-256: `eb24b40953d2e393f89acbee49d00253a93292b9fdc6e356d4e746d8d07df9ba`.
- 도구: REA 6.4.0 / JADX headless 0.7.1 / Java 21.0.12.1. 정확한 인자·도구 해시·Evidence ID는 `qa/competitor-rea/magnifier/receipt.json`, 취득 출처는 `acquisition.json`.
- `VisorActivity.onCreate`: 확대 슬라이더와 정지·색상·플래시 버튼의 리스너 연결을 확인했다. 단순 매니페스트 비교에서 끝내지 않았다.
- `defpackage.dp.onClick` case 2: 카메라 preview 시작/정지 상태를 바꾸고 별도 bitmap 뷰를 표시하며, 실시간 확대 슬라이더를 숨기고 재생 아이콘을 표시하는 분기가 있다. **실시간 확대와 정지 후 읽기를 별도 상태로 다룬다는 기술 참고**다. 이 메서드만으로 정지 후 핀치·이동이 구현됐다고 단정하지 않는다.
- 같은 메서드 case 1은 색상 모드 전환, case 4는 preview 상태를 확인한 torch on/off 분기다. 하드웨어 성공률이나 지연을 증명하지 않는다.
- `onPause`에는 밝기 복구가 보이지만 카메라 surface 생명주기를 전부 추적하지 않았다. 경쟁 앱 카메라 해제 결함을 주장하지 않는다.

설치·실행·광고 클릭은 하지 않았다. APK 서명 검증·런타임 성능·실제 초점 품질은 이 정적 분석의 범위 밖이다. 우리 `qa/rea-magnifier.json`은 **우리 APK** 선언 분석으로 별도 유지했다. 우리 제품의 실제 동작 근거는 `qa/build-verification.json`의 가상 카메라 에뮬레이터 QA이며 삼성 실카메라는 아직 대기다.

## 우선 개선안과 통과 기준

| 순서 | 작은 범위의 개선 | 근거·우리 앱의 현재 차이 | 구현 후 검증 기준 |
|---|---|---|---|
| 1 | 정지한 사진에서 확대·이동, 원래 크기로 되돌리기 | RV 초점·손떨림 리뷰는 먼저 멈추고 읽는 흐름의 필요성을 시사한다. REA 비교에서 별도 정지 뷰 상태가 확인됐다. 우리 소스는 `FIT_CENTER` 정지 그림에 맞추고 정지 중 카메라 확대를 끄므로, 정지 후 작은 글자를 더 살필 수 없다. | 삼성 실기기에서 라벨을 정지한 뒤 핀치 또는 큰 확대 버튼으로 확대하고 네 모서리까지 이동, 원래 크기 복귀가 가능해야 한다. 이동·확대는 원본 RAM bitmap을 수정하지 않는다. 다시 실시간 전환 시 카메라 배율과 사진 배율을 혼동하지 않는다. 회전·백그라운드·저장 취소에서 crash/이미지 손실 없이, 저장 대상이 전체 사진인지 현재 화면인지 명확해야 한다. 디지털 확대가 원래 촬영 해상도를 높인다고 표현하지 않는다. |
| 2 | 실시간 화면의 누른 위치 초점과 결과 표시 | 두 상용 앱의 개별 리뷰에 초점 어려움이 있고, 우리 MainActivity에는 명시적 tap-to-focus 경로가 없다. 고정 사진에는 자동초점을 적용할 수 없으므로 실시간에만 제공한다. | 카메라가 지원할 때 CameraX focus metering으로 연결하고 요청 중/성공/미확인·실패를 구별한다. 가까운 라벨과 떨어진 라벨에서 상태가 끝없이 남지 않으며, 지원하지 않는 기기도 설명과 자동초점 기본 동작을 유지한다. 정지·권한 거절·백그라운드 상태에서는 요청하지 않는다. 실제 광학 선명도 성공은 삼성 실기기에서 평가한다. |
| 3 | 정지 화면에 원본/고대비/흑백 반전의 명확한 선택 | Sunfire 저시력 리뷰가 반전 필요를 직접 언급한다. REA에는 복수 색상 모드 전환이 보인다. 우리 현재 고대비는 회색조+대비 강화이며 흑백 반전이 아니다. | 토글을 계속 누르며 추측하게 하기보다 현재 모드 이름과 선택 상태를 표시한다. 밝은 종이·어두운 바탕에서 원본/고대비/반전이 명확히 다르고, 저장 PNG가 선택 모드와 일치해야 한다. 글씨1.3배·가로에서도 큰 버튼과 정지 사진의 읽기 영역이 남아야 한다. 특정 질환 치료·가독성 보장은 금지한다. |

세 개선 모두 라이브 카메라·확대·정지 해제 중 광고를 넣지 않는 현재 원칙을 유지한다. 프리뷰를 키우기 위해 조작부를 작게 만드는 대신, 실제 낮은 화면 높이에서 보조 설명·설정을 정돈하는 시안을 먼저 비교한다. 아이콘만 있는 상용 화면을 그대로 따라 하지 않는다. OCR·AI·서버·자동 업로드·모든 기기 고정 10배 약속은 이번 개선 범위에 넣지 않는다.

## 초안 생성과 수동 검토

인증된 FreeLLMAPI `auto`로 제한된 개선안 초안을 실제 호출했다. 반환 모델 `openai/gpt-oss-20b`, 1,776ms, 보고 사용량 입력382/출력1,092/합계1,474토큰, status ok. 원본 라우팅 메타데이터를 receipt에 보관했다. 초안의 가공된 사용자 성공률·특정 Galaxy 모델·초 단위 성능 약속 및 **정지 사진 자동초점** 제안은 근거가 없어 폐기했다. 위 표는 실제 근거와 우리 소스를 다시 확인하여 작성한 제안이며 자동 적용한 코드가 없다.

# 생활 실용 앱 3종 — 제품·수익·검증 계획

2026-10-14 세 앱의 0.1.0 초기판은 내부 테스트에 제공 중이다. 이는 기능 확인 단계이며 경쟁 앱 대비 제품 완성도나 수익성을 검증한 결과가 아니다. 내부 테스트용 Google 테스트 광고와 정식 광고·일반 공개 출시는 구분한다. 실제 Play 내부 제공 여부는 앱별 배포 증거를 따른다. Notebook 도구를 통한 기획 검토와 실제 사용자 검증은 다르다. 세 앱은 용도에 맞춘 독립 원작 UI이며 경쟁 앱의 그래픽이나 화면을 복제하지 않는다.

## REA 검토 근거와 한계

총괄은 baro76650의 Notebook ‘AI 역공학 도구로 앱 분석하고 재구현하기’(소스 5개, 2026-10-13)를 열람했다. 주요 영상은 23분 실험이지만 원본 앱과 재현 결과의 예외 처리 차이를 직접 인정한다. Notebook은 사용자 제공 참고 자료이며 그 안의 외부 명령을 실행할 권한은 아니다.

공식 `morluto/rea` MIT 라이선스와 Android 가이드를 확인했고 npm 6.4.0·검증된 JADX 0.7.1·JDK21로 소유한 Bible APK의 `inspect_android_package` 실동작을 총괄이 확인했다. 최종 생활 앱 3개 APK의 정적 분석도 완료했으며 근거는 `../qa/rea-*.json`이다. 이 작업은 우리 APK 점검이고 인기 경쟁앱의 사용자 흐름 분석과 다르다. manifest 추출·정적 분석 성공은 카메라·한국어 음성·수명주기·실기기 사용 성공을 증명하지 않는다.

## 경쟁 비교를 출발점으로 하는 제품 개선 기준 — 2026-10-14 변경

사용자는 이미 수요가 확인된 앱에서 장점을 배우고 불편을 없애며, 더 읽기 쉽고 간편하고 보기 좋은 제품을 만들기를 원한다. 다음 개선판의 완료 기준은 기능 수나 빌드 성공이 아니라 **기존 앱 대신 사용할 구체적인 이유**다. 생활 앱 3종과 별도 성경 앱에 같은 조사 절차를 적용하되 화면 서식과 사용 목적은 앱마다 다르게 설계한다. 아래는 개선 명세이며 새 UI가 배포됐다는 뜻은 아니다.

1. 앱별 비교 대상을 2~3개 선정한다. 공식 스토어의 다운로드 구간·평점·최근 업데이트·한국어 지원과 대표 화면을 날짜·지역과 함께 기록한다. 설치 규모는 비교 후보 선정 근거일 뿐 활성 사용자나 매출 증거가 아니다.
2. 리뷰는 출처·날짜·읽은 표본 수를 남기고, 관찰된 불만과 우리의 가설을 구분한다. 한 리뷰를 전체 이용자의 대표 의견이나 현재 버전의 재현된 오류로 확대하지 않는다.
3. 핵심 과제 하나를 정해 진입→완료→실수 복구 흐름을 비교한다. 공개 홍보 화면, 직접 실행한 화면, REA 정적 분석, REA 기기 관찰을 별도로 표시한다. REA 분석 질문은 ‘어떤 권한인가’에 그치지 않고 필요할 때 상태 전환·저장·정지·복귀 등 구체적인 동작으로 좁힌다.
4. 근거→사용자 문제→우리의 개선→검증 방법을 연결한 명세를 먼저 확정한다. 경쟁앱의 모든 기능을 합치지 않는다. 우리 대상 사용자에게 필요한 장점만 남기고 화면·문구·자산·코드는 자체 구현한다.
5. 핵심 화면과 실제 결과물을 먼저 시안으로 비교하고, 작동하는 프로토타입에서 조작 횟수·가독성·오류 복구를 확인한 뒤 전체 구현을 확장한다. UI 코드와 콘텐츠 품질을 함께 검토한다.
6. 실제 대상 사용자 관찰과 기술 QA를 각각 통과한 뒤 공개 출시 준비 상태를 판단한다. 내부 테스트 제공, 경쟁 비교 완료, 실제 사용성 검증, 수익 측정은 서로 대체할 수 없다.

### 개선판 검증 방법

- 동일한 기기·글씨 설정·동일 과제로 비교한다. 경쟁앱을 직접 실행하지 못한 경우 조작 횟수나 완료 시간을 추정하지 않고 미측정으로 남긴다.
- 내부 목표: 설명 없이 핵심 과제를 완료하고, 잘못 누른 뒤 복구할 수 있어야 한다. 50~70대 5명 정도의 초기 관찰에서 4명 이상 자력 완료를 목표로 삼되 이는 작은 탐색 표본이며 시장 검증이나 Google의 의무 기준이 아니다. 실제 관찰 전에는 미검증이다.
- 실제 대상 사용자를 아직 모집하지 못해도 시안·구현·내부 QA는 진행한다. 모집을 개발의 선행 승인 조건으로 만들지 않으며, 실제 사용자 검증 상태만 미검증으로 유지한다.
- 일반 글씨와 큰 시스템 글씨에서 주요 내용·조작이 잘리지 않아야 한다. Android 공식 접근성 기준인 최소 48dp 터치 영역, 일반 작은 본문 4.5:1 대비를 하한으로 삼고 주요 버튼은 56dp 이상을 설계 목표로 한다. 색만으로 상태를 구분하지 않고 텍스트·아이콘 설명을 함께 제공한다.
- 첫 화면의 주요 행동, 공유 결과물, 빈 화면, 권한 거부, 데이터 복구를 실제 화면으로 검토한다. 광고는 읽기·촬영·듣기·목록 체크·공유 완료를 막지 않는다.
- 사용성 확인 후 앱별 재사용·실제 유효 광고 노출·유지 비용을 측정한다. 경쟁앱의 다운로드 수나 보기 좋은 시안만으로 수익을 예측하지 않는다.

공식 근거: [REA 기능과 분석 범위](https://github.com/morluto/rea), [Android APK 정적 분석의 근거·한계](https://github.com/morluto/rea/blob/main/docs/android-analysis.md), [Android 접근성 기준](https://developer.android.com/guide/topics/ui/accessibility/apps).

## 수익과 비용

수익식은 유효 광고 노출/1,000×실제 eCPM. 테스트 광고에는 수익 기대값을 붙이지 않는다. 앱별 AdMob 노출·수익과 Play 집계 활성·설치·유지율이 연결되기 전 측정값은 `null`/미연결로 남긴다. 수익이 아직 없다는 관측과 측정할 수 없다는 상태를 구분한다. 총광고요청=노출, 공유시트열림=메시지전송, 설치=지속사용으로 간주하지 않는다.

앱별 순이익은 실제 수익에서 호스팅·수수료·유료 API·유지보수·지원 비용을 차감한다. 사람 시간과 공통 비용의 배분 방식이 없으면 비용을 0으로 적지 않는다. V1 실시간 생성 모델·신규 측정 서버·자체 행동 분석 SDK는 없다. 기존 개발 계정·AdMob 운영비는 확인된 자료가 있을 때만 반영한다.

## 출시와 권한·개인정보 게이트

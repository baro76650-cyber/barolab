## 자산·표시 검토

각 앱의 원작 Android 벡터 아이콘을 바탕으로 `apps/store-assets/{앱}/icon-512.png`와 `feature-1024x500.png`를 SVG로 제작했다. 크기·해시는 `store-assets/manifest.json`에 기록한다. 경쟁사 사진·화면·브랜드 자산은 사용하지 않았다. 실제 스크린샷은 빌드 담당이 촬영한 원본만 사용한다. 코드로 만든 기능 그래픽을 앱 실행 화면으로 표시하지 않는다. Console의 AI 관련 질문은 실제 제작 과정과 해당 질문의 범위에 맞춰 총괄이 답한다.

`qa/rea-greeting.json`, `rea-magnifier.json`, `rea-shopping.json`의 실제 APK 정적 분석은 각각 패키지와 versionCode1, `0.1.0-internal-preview`, min26/target36을 확인한다. 공통 `INTERNET`/`ACCESS_NETWORK_STATE`, 돋보기 `CAMERA`, 장보기 `RECORD_AUDIO`를 확인했다. `com.google.android.gms.permission.AD_ID`는 제거됐지만 합쳐진 APK에는 `android.permission.ACCESS_ADSERVICES_AD_ID`와 `ACCESS_ADSERVICES_ATTRIBUTION`, SDK의 WAKE_LOCK/FOREGROUND_SERVICE 등이 남아 있다. 모든 광고 식별자 수집을 막았다고 설명하지 않는다. 권한 존재만으로 실제 각 API 호출·업로드를 증명하지도 않는다. 최종 빌드를 다시 만들면 REA 증거 APK SHA와 배포 파일이 같은지 재확인해야 한다.

| 전송 암호화 | SDK 처리에 대해 예 근거: GMA는 전 데이터 TLS 전송 명시 | 동일. 로컬 카메라 접근은 전송 암호화 질문 대상이 아님 | **SDK는 TLS이나 네트워크 음성 제공자의 전송은 아직 미확인. 전체 수집 데이터에 ‘예’를 기계적으로 선택하지 말 것** |
| 삭제 요청 경로 제공 | 예 후보: 공개 정책의 이메일 단계와 운영자 보유 문의 메일 삭제 접수. Google 기록 일괄 삭제 기능을 뜻하지 않음 | 동일 | 동일. 음성 제공자 기록의 삭제 통제와 구분 |

선택 수집은 모든 기기·지역 사용자에게 제공/거부 선택권이 있어야 한다는 공식 기준이다. EEA 일부 동의 화면만으로 SDK 전체 수집을 ‘선택’으로 바꾸지 않는다. 돋보기의 직접 opt-in 경로는 다른 두 앱과 구분한다. 삭제 요청 경로는 이메일도 가능하다는 공식 FAQ에 근거하지만 실제 운영자가 접수·범위 확인·회신할 수 있어야 한다. 계정 없음이나 SDK 삭제 API 부재만으로 삭제 요청 경로가 없다고 단정하지 않는다.

### 로컬 기능·공유·음성의 분리

| 데이터/동작 | 선언 검토 |
|---|---|
| 안부 이름·카드 문구·즐겨찾기 | 기기 안에서만 처리하고 외부 전송하지 않는 데이터는 그 자체를 off-device 수집으로 선언하지 않는다. 사용자가 명시적으로 선택한 다른 앱 공유·파일 저장은 해당 동작과 제공자 처리를 별도 공개한다. 광고 SDK 수집을 없애는 근거는 아님 |
| 돋보기 카메라·정지 프레임 | CAMERA 권한과 로컬 RAM 접근은 사진/영상의 외부 수집을 뜻하지 않는다. 앱 자동 저장/업로드 없음. 선택 SAF 위치가 클라우드인 경우 그 제공자 처리를 설명하며 운영자 서버 업로드로 바꾸어 표현하지 않음 |
| 장보기 항목·수량·체크·undo | 기기 로컬 데이터이며 광고·운영자 서버에 전송하지 않음. 공유한 텍스트 사본은 받는 앱 처리와 구분 |
| 장보기 온디바이스 음성 | 전용 on-device recognizer가 성공한 경로에서는 음성을 외부로 보내지 않음. 서비스 존재가 한국어 모델 지원을 보장하지 않으며 실제 성공은 실기기 검증 필요 |
| 장보기 선택 네트워크 음성 | 일반 SpeechRecognizer는 원격 서버 처리 가능. **오디오 → 음성/녹음의 선택 수집, 앱 기능 목적**을 보수적 선언 후보로 검토. 앱이 파일을 저장하지 않는 것과 제공자가 수집하지 않는 것은 다름. 서버 보관이 일시 처리라는 근거는 없으므로 ‘일시 처리 예’ 확약 금지 |

Play는 사용자 주도 명시적 동작/고지·동의가 있는 제3자 전송에 공유 예외를 둘 수 있다. 이 예외는 **수집이 없다는 뜻이 아니며**, 모든 음성 제공자를 개발자 지시만 따르는 서비스 제공자로 간주할 근거도 없다. 선택 음성의 공유 항목은 실제 제공자·통합 방식·고지 충족을 확인한 뒤 적용한다. [Android SpeechRecognizer 공식 문서](https://developer.android.com/reference/android/speech/SpeechRecognizer)는 원격 음성 전송 가능성을 명시하고 [RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent)의 `EXTRA_PREFER_OFFLINE`은 제공자가 무시할 수 있다. 따라서 장보기의 ‘전체 전송 암호화’와 음성 제공자 보관/삭제는 **미확정 항목**이다. 광고 SDK TLS를 음성 제공자까지 확대해 답하지 않는다.

### 제출 직전 남은 확인

1. 최종 배포 빌드와 REA/merged manifest·SDK 버전 일치, 세 앱 개인정보 HTTPS 접근 확인.
2. 장보기 실제 음성 제공자 처리·TLS·보관/삭제를 확인하거나 미확정 경로에 대해 보수적으로 선언. 이번 표는 불명확한 사실을 대신 확정하지 않는다.
3. Console의 현재 질문 문구와 수집/공유 예외·필수/선택 범위를 한 항목씩 대조. 광고 있음·계정 없음·성인 대상·의료 기능 아님과 실제 앱을 일치시킨다.
4. 공개 정책의 문의 메일 접수와 삭제 요청 경로를 실제 운영 가능한 상태로 유지. 앱 로컬 데이터 삭제와 SDK/음성/공유 사본 삭제를 구분한다.

실제 인증 FreeLLMAPI bounded 검토 초안을 수령했다. 후보가 ‘돋보기 카메라가 광고 버튼을 눌러야 접근한다’, ‘모든 트래픽 TLS’, ‘로컬 이름을 수집’처럼 경로를 섞어 설명한 부분은 폐기했다. 위 내용은 공식 문서와 실제 소스·REA를 수동 대조한 선언 검토안이며 승인을 보장하지 않는다.

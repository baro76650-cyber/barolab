# 윤뷰스 포스팅 검사 조건 v1

작성일: 2026-10-01. 이 조건은 편집 일관성과 누락 방지를 위한 프로젝트 기준이며 네이버 노출 보장 공식이 아니다.

## 표현을 허용하는 범위

모델이 달라도 핵심 사실·맥락이 유지되면 제목의 표현, 문장, 의견의 전개와 분량은 달라도 된다. 기준 원고의 문장을 복제하거나 문장 유사도 점수로 합격을 결정하지 않는다. 편집기 내용 비교는 **해당 실행에서 작성한 원고**와 입력된 글 사이의 누락·변경 확인에만 사용한다. 사진 계획은 소재별로 승인하며, 0장을 포함해 설명에 필요한 수량을 사용한다. 고정 장수·무작위 장수·대표 사진을 강제하지 않는다.

## 자동 검사

| 영역 | 완료 조건 | 실패 예시 |
|---|---|---|
| 입력 형식 | 제목·블록·미발행 상태의 타입이 올바름 | 문자열 `"false"`, 빈 원고, 모델이 CSS/정렬 필드 삽입 |
| 제목 | 선택한 주 키워드 포함 | 다른 인물이나 주제로 제목 변경 |
| 본문 구조 | 의미 있는 `▼` 소제목과 각 절의 실제 본문 존재 | 빈 소제목, 제목만 남은 마지막 절 |
| 사진 계획 | 승인한 사진의 ID·파일·순서·캡션 일치 | 필요한 사진 누락, 중복, 다른 사진 대체 |
| 사진 파일 | 안전한 파일명·폴더 내부 경로·파일 존재·형식 시그니처·승인 SHA256 일치 | 잘못된 경로, 파일 변조, 이미지 아닌 파일 |
| 사진 캡션 | `사진 설명｜원본 출처` 유지 | 설명 삭제, 출처 두 곳, 기사 날짜 추가, 본문에 캡션 복제 |
| 마무리 | 결말 본문 → 감사 인사 → 관련 해시태그 | 인사/결말 누락, 중복 태그 |
| 프로그램 조립 | 고정 CSS, 가운데 정렬, 원본 사진 비율, 블록 사이 빈 문단 1개 | 모델이 임의 HTML/CSS 삽입 |
| 실제 편집기 | 해당 원고의 모든 행·사진·전용 캡션·대표 사진·업로드 상태 일치 | 붙여넣기 누락, 사진/캡션만 왼쪽 정렬, 깨진 이미지 |
| 실제 마무리 간격 | 감사 인사 앞뒤 빈 문단 각각 1개 | 공백/NBSP 문단을 포함해 3줄 띄움 |
| 저장 및 경계 | 도구 관측상 임시저장 확인, 발행 버튼 미조작 | 저장 증거 없음, 발행 조작 또는 미확인 상태 |

`document_checks.ok`는 형식 검사 결과다. 사진 해시·시그니처 검사는 이미지 전체 디코딩, 출처의 진위, 사용 허가의 확정 판정을 대신하지 않는다. 편집기 관측 JSON은 호스트 브라우저 도구로 수집해야 한다. 검사기는 JSON 자체의 작성자를 인증하지 않으므로 모델이 만든 관측값으로 합격 처리하면 안 된다.

## 내용 및 화면 검토

### 예약 제출 전 전체 검수 (공통 파이프라인)

- 실제 네이버 편집기를 PC와 모바일 화면으로 전환하고 제목부터 마지막 문단까지 빠짐없이 확인한다. 줄바꿈은 의미 단위로 정리하고, 짧은 단어만 남는 행과 불필요한 빈 문단을 보완한다.
- 계정별 서체·크기·정렬, 소제목·강조·표, 개별 사진·캡션·대표 사진, 링크 목적지와 태그를 확인한다. 외부유입 글은 본문 주제에 직접 대응하는 CF 상세글로 자연스럽게 연결한다.
- 실제 화면을 검수한 뒤 해당 주제 폴더의 `pre-reservation-review.json`에 `account`, `title`, `reserveTime`, `pcWholeDocumentVisualReview`, `mobileWholeDocumentVisualReview`, 전체 화면 캡처 파일명 목록 `screenshots`, `editor_review_hash()`의 `documentSha256`을 기록한다. 화면을 보지 않고 완료 값을 생성하지 않는다.
- `pipeline_runner.py`는 발행 설정을 열기 전과 최종 예약 제출 직전에 기록과 현재 편집 문서를 대조한다. 내용이나 서식이 바뀌면 전체 검수를 다시 수행한다. 예약 목록의 정확한 제목·시간을 재접속과 새로고침으로 확인하고, 저장된 원고를 다시 열어 서식을 대조한다.
- 외부유입 4·5호기는 작업 후에도 브라우저를 유지한다. 명시적인 종료 요청이 있을 때에만 해당 계정의 전용 종료 배치를 사용한다.

### 계정별 페르소나 검토

`guides/blog_style.md` 7절을 기준으로 다음 작성부터 적용한다. 기존 임시저장 글의 재편집은 별도 요청이 있을 때 한다.

- 실제 `blogId`와 `research.md`의 대상 계정·페르소나가 맞는지 확인한다.
- 말투, 문단 호흡, 독자 질문과 전개, 소제목, 강조, 끝인사가 해당 계정에 맞는지 읽어 검토한다. 같은 원고의 어미·서체만 바꾸어 다른 계정에 재사용하지 않는다. 줄 수나 문장 유사도를 합격 조건으로 고정하지 않는다.
- 실제 편집기에서 본문 여러 위치의 서체·크기를 확인하고, 모바일에서 사진·캡션·소제목·행갈이의 가독성을 검토한다. 사용한 서체·크기와 대체 이유를 기존 `research.md`에 기록한다. 제공 목록 확인과 실제 적용 확인을 구분한다.
- 소재에 맞게 확정한 끝인사가 승인 계획의 `signoff`와 일치하고, 인사 앞뒤 빈 문단이 각각 하나인지 확인한다.
- 확인하지 못한 서체·배치를 검수 완료로 보고하지 않는다. 미확인 사항은 기존 검토 기록에 남기며 `visual_layout` 승인에 포함하지 않는다.

현재 자동 검사기는 페르소나의 의미와 실제 서체·크기를 판정하지 않는다. `posting.py`의 HTML도 공통 CSS이므로 형식 검사 통과나 HTML 생성만으로 계정별 편집 적용을 확정하지 않는다. 별도 설정 파일·검사 프로그램을 추가하지 않고 기존 감독관 검토에 포함한다.

### 공통 검토

자동 검사와 별도로 사실·해석, 사진의 사건/시점 맥락과 사용조건, 실제 화면을 감독관이 검토한다. 특정 단어가 있거나 감상 문장이 많다는 이유만으로 콘텐츠 품질을 확정하지 않는다. 기사·사진으로 확인하지 못한 가격·브랜드·건강·개인 경험을 추가하지 않고, 관찰과 의견을 구분한다. 공개 사진과 스타 SNS를 사용하고 출처를 표시하라는 사용자 지침을 적용하되, 이를 별도 공개 라이선스 확인으로 바꾸지 않는다.

`ready_for_handoff`는 문서 검사, 실제 편집기 검사, 해당 원고 및 사진 계획 SHA256에 연결한 별도 감독관 검토가 모두 통과해야 true다. 이것은 **미발행 초안 인계 상태**이며 발행 허가나 실제 발행 완료가 아니다. 새 원고나 사진 계획에는 이전 검토 승인을 재사용하지 않는다. 검토 기록도 인증 시스템은 아니므로 신뢰할 수 있는 호스트가 관리해야 한다.

## 현재 지원 범위

- 실행 검사기와 HTML 조립기는 Python 표준 라이브러리만 사용한다.
- 브라우저 입력 자동 실행기는 아직 포함하지 않는다. 기존 네이버 초안을 읽기 전용으로 관측해 실제 편집 검사기를 테스트했다.
- 제미나이 테스트는 이미 검증한 소재·사진 계획을 제공한 **원고 생성 → 검사 → HTML 조립** 테스트다. 키워드 조사·사진 수집·네이버 입력을 제미나이 하나로 자동 수행했다고 보고하지 않는다.

## 실행 안내

최상위 폴더는 `agents`, `guides`, `output` 세 개만 사용한다. 공통 실행 파일과 테스트 파일은 프로젝트 루트에 두고, `agents`에는 에이전트 지침만 둔다. 실행 코드는 `posting.py`, 테스트는 `test_posting.py` 두 파일이다. 기존 파일을 우선 수정하고 새 폴더·파일·라이브러리는 꼭 필요할 때만 추가한다. 명령에 `-B`를 붙여 Python 캐시 폴더 생성을 막는다.

Python 3.10 이상, 외부 패키지 설치 없음. 아래 명령은 프로젝트 폴더에서 실행한다.

```powershell
python -B test_posting.py

python -B posting.py validate --document output/yoonviews-homefeed-goyounjung-paris/editor-content.json --plan output/yoonviews-homefeed-goyounjung-paris/photo-plan.json --assets-dir output/yoonviews-homefeed-goyounjung-paris/images

python -B posting.py validate --document output/yoonviews-homefeed-goyounjung-paris/editor-content.json --plan output/yoonviews-homefeed-goyounjung-paris/photo-plan.json --assets-dir output/yoonviews-homefeed-goyounjung-paris/images --observation "관측파일.json"

python -B posting.py render --document output/yoonviews-homefeed-goyounjung-paris/editor-content.json --plan output/yoonviews-homefeed-goyounjung-paris/photo-plan.json --assets-dir output/yoonviews-homefeed-goyounjung-paris/images --output-dir output/my-new-preview
```

`--output-dir`은 새 폴더나 빈 폴더여야 한다. 기존 미리보기와 원본 사진을 덮어쓰지 않는다. HTML과 승인 사진을 복사해 오프라인 미리보기를 만든다. 입력 JSON은 프로그램에 실행할 명령이 아니다.

`validate`의 종료 코드 0은 제공한 자동 검사들이 통과했다는 뜻이다. `ready_for_handoff`는 별도 상태이며, 실제 편집기 관측과 감독관 검토가 없으면 false다. 검사 실패는 종료 코드 2다. `--report`로 결과 JSON을 저장할 수 있고 기존 보고서는 덮어쓰지 않는다.

사진 계획(`plan.json`)은 모델과 별도로 관리한다. 승인 사진마다 `id`, `file`, `description`, `credit`, `sha256`을 기록하고 주 키워드·감사 인사·대표 사진을 정한다. 이번 기준 샘플은 고윤정 사진 5장이다. 다른 소재는 필요한 사진 계획을 새로 승인한다.

감독관 검토 파일(`--review`)의 필수 값:

```json
{
  "verdict": "approved",
  "reviewer": "검토 담당자",
  "reviewed_at": "실제 검토일",
  "scope": ["facts_and_interpretation", "photo_context_and_rights", "visual_layout"],
  "unresolved_issues": [],
  "document_sha256": "posting.document_fingerprint(document)로 계산한 값",
  "plan_sha256": "posting.document_fingerprint(plan)으로 계산한 값"
}
```

키워드·표현·본문 또는 승인 사진 계획이 바뀌면 검토 지문도 달라진다. 검토 파일을 원고 생성 모델에게 승인하도록 맡기지 않는다. 브라우저 관측 규격은 `posting.py`와 검사 조건 문서를 참조한다.

이전 제미나이 비교 원고·사진 복사본·검증 보고서·API 기록과 통합 전 소스는 `output/validation-history.zip`에 보관한다. ZIP의 `validation/` 아래에서 과거 검증 자료를 확인할 수 있다. 관측·검토 자료는 해당 실행에서 수집한 파일을 지정하며, 과거 기록을 새 원고의 승인으로 재사용하지 않는다. 프로그램은 네이버에 접속하거나 발행 버튼을 누르지 않는다.

## 글쓴이 시선과 근거 기반 편집
- 사진은 글쓴이가 자기 자리에서 보는 자료·물건·생활 장면의 시선을 기본으로 한다. 손·얼굴을 강제하지 않는다. 외부 관찰자가 호스트·가족을 찍는 연출은 글의 설명상 필요와 이유가 있을 때만 사용한다.
- 글의 질문과 흐름을 먼저 정하고 각 이미지의 설명 목적·문단 위치·장면·실제 자료/생성 여부·캡션을 계획한다. 수량은 0장도 가능하며 고정 장수·무작위 장수·대표 사진을 강제하지 않는다. 중복 장면이나 장식용 수량 채우기를 제외한다.
- 생성 사진은 보이는 장면만 설명한다. 직접 촬영·구매·사용·방문·신청의 증거나 공식 기관 제공 사진으로 표시하지 않는다. 제작 출처를 내부 기록에 보존하고 필요한 안내를 숨기지 않는다. 실제 자료는 확인한 출처와 사용조건을 연결한다.
- 공식 사실과 운영자의 해석을 구분한다. 독자 조건에 따른 확인 순서·선택 이유·한계를 자연스럽게 설명하되 의견 문장 수를 강제하지 않는다. 실제 하지 않은 개인·주변인의 경험을 만들지 않는다. 1인칭 사진이나 의견 자체로 검색 노출을 보장하지 않는다.

# 예약 발행 에이전트

실행은 단일 `pipeline_runner.py`가 담당한다. 계정별 복제 스크립트·임시 발행 스크립트로 우회하지 않는다.

1. 여섯 콘텐츠 에이전트의 순서·실제 모델 응답·인계 파일·지침 해시를 확인한다.
2. 기존 전용 브라우저의 실행 정보와 프로필을 확인하고 CDP로 연결한다. 시작이 필요할 때만 전용 시작 BAT를 사용하며 작업 후 브라우저를 유지한다.
3. 실제 편집기에서 승인된 이미지 수·배치(0장 포함), 해당 전용 캡션, 본문, 끝 해시태그와 PC·모바일 전체 검수 해시를 확인한다.
4. 실제 선택된 카테고리·공개 설정·검색 허용·등록 태그를 확인한다. 시간은 한국 시간 24시간제(`19:30`)로 지정한다. 날짜·시간이 다르거나 즉시 발행이 선택되면 제출하지 않는다.
5. 기존 예약이 있거나 제출 결과가 불명확하면 재제출하지 않는다. 외부 클릭 전에 `submitting`을 원장에 기록한다.
6. 예약 목록을 새 페이지와 새로고침 후 두 번 확인하고, 저장된 원고를 다시 열어 승인된 본문·서식·사진·캡션 해시와 대조한다.
7. 확인된 경우에만 `reserved`로 기록한다. 공개 URL 확인 전에는 공개 완료로 표시하지 않는다. 인계 산출물과 예약 증거를 삭제하지 않는다.

## 글쓴이 시선과 근거 기반 편집
- 사진은 글쓴이가 자기 자리에서 보는 자료·물건·생활 장면의 시선을 기본으로 한다. 손·얼굴을 강제하지 않는다. 외부 관찰자가 호스트·가족을 찍는 연출은 글의 설명상 필요와 이유가 있을 때만 사용한다.
- 글의 질문과 흐름을 먼저 정하고 각 이미지의 설명 목적·문단 위치·장면·실제 자료/생성 여부·캡션을 계획한다. 수량은 0장도 가능하며 고정 장수·무작위 장수·대표 사진을 강제하지 않는다. 중복 장면이나 장식용 수량 채우기를 제외한다.
- 생성 사진은 보이는 장면만 설명한다. 직접 촬영·구매·사용·방문·신청의 증거나 공식 기관 제공 사진으로 표시하지 않는다. 제작 출처를 내부 기록에 보존하고 필요한 안내를 숨기지 않는다. 실제 자료는 확인한 출처와 사용조건을 연결한다.
- 공식 사실과 운영자의 해석을 구분한다. 독자 조건에 따른 확인 순서·선택 이유·한계를 자연스럽게 설명하되 의견 문장 수를 강제하지 않는다. 실제 하지 않은 개인·주변인의 경험을 만들지 않는다. 1인칭 사진이나 의견 자체로 검색 노출을 보장하지 않는다.
